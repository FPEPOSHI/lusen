API documentation that people, search engines and AI agents can all read.

Lusen reads your routes, form requests and resources and writes static HTML for people, Markdown and OpenAPI for machines, llms.txt for retrieval models and an MCP server for agents. Zero configuration. No database. No JavaScript needed to read a page.

Three readers, one build

Most API docs tools write for a developer with a browser. Lusen writes for three audiences at once, from one description of your API, so none of them gets a lesser copy.

People

Server-rendered HTML, one page per endpoint and one per group, readable with JavaScript off. Request examples in six languages, a search box that needs no server, and an optional playground.

Search engines

Canonical URLs, real meta descriptions, JSON-LD and a sitemap. One page per question, so nothing competes with itself for a query.

AI agents and generative search

A Markdown twin of every page (swap .html for .md), llms.txt, OpenAPI 3.1, a discovery document at /.well-known/api-docs, and an MCP server that answers with the same Markdown a person reads.

Worked out, not written

Extraction is static analysis of your source. A build never boots the application, so it runs in CI against a checkout with no .env, and it reads more than you would think to write down.

  • Request bodies from form request rules, nested shapes like items.*.product_id included.
  • Response fields from API resources, typed from model casts and migrations.
  • Authentication and scopes from middleware, and rate limits from throttling.
  • API versions from URLs: which is current, which are deprecated, and which operation supersedes which.
  • Real examples recorded from your own test suite, so an example says "paid" rather than "string".
  • A contract diff that grades every change by what it costs a client, for CI.

Where inference stops, attributes and docblocks have the last word, including the ones another tool left behind.

Try it on your own application

composer require fpeposhi/lusen
php artisan lusen:build

That is the whole setup. Lusen discovers api/* routes and documents them with no configuration, writing to public/docs so your web server serves flat files with no PHP on the request path.
